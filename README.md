## Overview

SAR-TopoEdgeKAN combines pre-event and flood-event-period SAR, DSM elevation and slope to reconstruct flood depth within a supplied flood range. A topographic graph uses learnable KAN functions on its edges to guide feature aggregation, while a terrain-derived depth prior supports the final prediction.

The repository includes the main model, five neural comparison models, three deterministic terrain methods, and ablation and controlled-comparison configurations. Experiments use fixed training, validation and test sets with repeated random seeds.

**Benchmark scope:** every method receives a supplied flood range. In FloodDepthNet, this range is derived from reference-label support (`valid_depth_mask`), so the experiments evaluate **known-range flood-depth reconstruction**. They do not evaluate automatic inundation-extent detection. Depth labels are satellite-derived reconstructions, rather than field measurements.

## Method

The main model contains five stages:

1. **Temporal SAR encoding:** jointly encode pre-event and event-period VV/VH observations and SAR change features at multiple scales.
2. **Terrain encoding:** build a separate feature pyramid from DSM, slope and mask-aware terrain context.
3. **Topographic edge KAN:** aggregate bottleneck features over an eight-neighbour graph, with KAN edge functions learning corrections from physical terrain descriptors.
4. **Gated decoding:** combine SAR and terrain features through independent validity-aware gates and multi-scale skip connections.
5. **Prior-guided depth prediction:** estimate a componentwise boundary-elevation prior and learn a bounded multiplicative depth correction within the supplied range.

The default main model has approximately **1.45 million trainable parameters**. The KAN functions operate on graph edges; the graph is a learned aggregation mechanism rather than a hydraulic solver. See [model details](docs/MODEL.md) for the implemented structure.

## Installation

An example environment uses Python 3.10. Install a CUDA-enabled PyTorch build compatible with your GPU and driver, then install the repository dependencies:

```bash
conda create -n sar-topoedgekan python=3.10
conda activate sar-topoedgekan
python -m pip install -r requirements.txt
export MKL_THREADING_LAYER=GNU
```

The default repeated-seed and discussion experiment controllers require CUDA. Run the commands below from the repository root.

### Contents and Fixed Splits

| Split | Samples | Source events |
| --- | ---: | ---: |
| Training | 4,084 | 457 |
| Validation | 584 | 65 |
| Test | 1,167 | 130 |
| **Total** | **5,835** | **652** |

The released manifest defines the fixed splits. Source event IDs do not overlap between splits; event-chain IDs may span splits. Repeated seeds change training randomness, while sample membership remains fixed.

Each sample contains seven aligned GeoTIFFs:

| Directory within each split | Bands, in order |
| --- | --- |
| `S1/T1/` | `VV_pre_db`, `VH_pre_db` |
| `S1/T2/` | `VV_event_db`, `VH_event_db` |
| `S1/change/` | `VV_delta_db`, `VH_delta_db`, `anomaly_raw` |
| `S1/QA/` | `event_observation_count`, `selected_event_day_offset` |
| `DEM/` | `elevation_m_DSM`, `slope_deg` |
| `label/` | `depth_m` |
| `masks/` | `valid_depth_mask`, `DEM_valid_mask`, `slope_valid_mask`, `S1_event_composite_valid_mask` |

Patches are **256 × 256 pixels at 20 m spacing**, with CRS `EPSG:27704`. T1 is the pre-event SAR composite; T2 is a flood-event-period composite. Elevation is from Copernicus GLO-30 DSM. Floating-point rasters use NoData = `-9999`; embedded validity masks must also be respected. Missing reference depths must not be treated as dry pixels.

The archive includes a dataset README, the fixed sample manifest, band metadata, frozen training-only normalization statistics and `SHA256SUMS`.

### Preparation

Extract the archive and prepare the data contract:

```bash
unzip FloodDepthNet.zip -d data
python tools/prepare_flooddepthnet_s1_terrain_assets.py
```

This uses `data/FloodDepthNet/`, verifies the published metadata, raster checksums, band schema and spatial alignment, and binds the dataset contract to the released manifest. It copies the supplied training statistics without recomputing normalization or changing the split. It does not require any additional release files beyond those in the archive.

The shared dataset configuration is [configs/base/datasets/flooddepthnet_s1_terrain.xml](configs/base/datasets/flooddepthnet_s1_terrain.xml). If you choose a different dataset location, pass it through `--dataset-root` when preparing the assets and update `dataset.root` and `dataset.manifest` in this XML accordingly. Keep data fingerprints enabled.

After preparation, check the implementation with:

```bash
python -m pytest -q tests
```

## Training

Train the main model:

```bash
python train.py configs/sar_topo_edge_kan.xml
```

Train a neural comparator or the formal graph-removal ablation:

```bash
python train.py configs/compare/deep_learning/unet_depth_regression.xml
python train.py configs/ablation/sar_topo_edge_kan_wo_tae_kan.xml
```

All learned configurations share the fixed split, frozen normalization, objective, optimizer, learning-rate schedule and checkpoint-selection protocol. Checkpoints are selected on validation data. See the [comparison protocol](docs/COMPARISON_PROTOCOL.md) for the exact settings and the distinction between standard and matched-observation comparators.

## Repeated-Seed Experiments

Run five paired seeds for the main model, five neural comparators and formal graph-removal ablation:

```bash
python validate_random_seeds.py 5
```

Resume the newest unfinished campaign:

```bash
python validate_random_seeds.py --resume
```

The controller evaluates validation-selected checkpoints on the fixed test set and writes per-seed and aggregate reports, including `metrics_by_seed.csv` and `metrics_summary.csv`. The number of seeds controls repeated training runs, not dataset folds.

## Validation and Testing

Evaluate an individual model using its XML configuration:

```bash
python evaluate.py configs/sar_topo_edge_kan.xml
```

For this configuration, the default evaluation split is **validation**. For individual test evaluation, set `runtime.evaluation.split` to `test`; use `runtime.evaluation.checkpoint` to select a specific compatible checkpoint. Otherwise, the evaluator locates the latest completed training run.

To compare completed standalone neural runs and the three deterministic methods on the common **test set**:

```bash
python test.py runs/sar_topo_edge_kan/train
```

The neural comparators are U-Net, Attention U-Net, LinkNet, U-Net++ and ResNet18 depth regression. The deterministic methods are FwDET v2, TSA and FlDepth, implemented as local DSM adaptations. Deterministic methods do not require training or repeated training seeds. Implementation sources are documented in [comparison sources](docs/COMPARISON_SOURCES.md).

Reports include pixel-level MAE, RMSE, bias and R², event-averaged errors, and depth-stratified metrics on the common valid-depth domain.

## Inference

Run inference for a sample listed in the dataset manifest:

```bash
python tools/infer_sar_topo_edge_kan.py \
  --config configs/sar_topo_edge_kan.xml \
  --checkpoint CHECKPOINT.pth \
  --input SAMPLE_ID \
  --save-geotiff
```

Replace `CHECKPOINT.pth` with a compatible trained checkpoint and `SAMPLE_ID` with a manifest sample ID or raster basename. The command loads the corresponding aligned inputs and supplied flood range, then exports the prediction with georeferencing. It does not accept arbitrary unregistered raster inputs.
